# AIUEO Learn

Веб-приложение для изучения хираганы и катаканы.

- **React + TypeScript + Vite**
- Архитектура **Feature-Sliced Design (FSD)**
- Переиспользуемый UI-кит на **CSS Modules** + дизайн-токены (**CSS-переменные**), с поддержкой светлой/тёмной темы
- Максимальная типизация: без `any`, все сущности описаны интерфейсами

## Запуск

```bash
npm install
npm run dev      # dev-сервер
npm run build    # сборка + проверка типов
npm run test     # юнит-тесты (vitest)
npm run lint     # eslint
```

После `npm run dev` приложение доступно на http://localhost:5173.

## Структура (FSD)

```
src/
  app/            # Инициализация: корневой компонент, провайдеры, глобальные стили
    styles/       #   tokens.css (дизайн-токены), global.css (сброс стилей)
  pages/          # Страницы (композиция фич и энтити)
    trainer/      #   «Тренажёр»
    reference/    #   «Азбуки» (таблицы)
  widgets/        # Переиспользуемые блоки интерфейса
    app-header/   #   Шапка, навигация
  features/       # Фичи — пользовательские сценарии
    trainer/      #   Тренажёр: настройка → сессия → результаты
      model/      #     типы, генерация вопросов, хуки (useTrainerDraft, useTrainingSession, useTrainerPage)
      ui/         #     TrainerSetup, TrainingSession, TrainerResults, ...
    theme/        #   Переключение тёмной/светлой темы
  entities/       # Бизнес-сущности
    kana/         #   Знаки: базовые / озвончённые (дакуон/хандакуон) / ёон,
                  #   с позицией row/column в годзюоне + KanaTable
    progress/     #   Прогресс изучения: типы, localStorage, провайдер, mastery
  shared/         # Переиспользуемый код
    api/          #   Слой общения с бэкендом (client, endpoints, types) — заглушка
    lib/          #   Утилиты (cx, random) и хелперы
    ui/           #   UI-кит: Button, Card, Checkbox, SegmentedControl, ProgressBar, ...
```

Правило видимости FSD: слой может импортировать только себя и нижележащие
(`shared` — базовый, `pages` — самодостаточные). Фичи не импортируют друг друга,
страницы собирают фичи и энтити.

## Слой API

Пока приложение работает полностью локально, файлы в `src/shared/api/` — это
каркас для будущего бэкенда. Когда появится сервер, достаточно указать
`VITE_API_BASE_URL` и описать эндпоинты в `endpoints.ts` (например, для сохранения
прогресса).

## Логика тренажёра

На экране настройки пользователь выбирает:

1. **Азбуку** — хирагана, катакана или обе сразу;
2. **Набор знаков** — базовый годзюон, озвончённые (дакуон/хандакуон) или ёон;
3. **Знаки** — отметка по одному, целой **строкой** или целой **колонкой**
   таблицы годзюона (клик по заголовку строки/колонки), либо «все/снять»;
4. **Режим** — вбить ромадзи по знаку, выбрать знак по ромадзи или «Смешанный»
   (для каждого знака случайно выбирается один из двух типов);
5. **Количество повторений** (по умолчанию 10).

Каждый выбранный знак повторяется `repetitions` раз, порядок перемешивается.
После каждого ответа показывается обратная связь, в конце — сводка и список
ошибок для повторения.

## Наборы знаков

У каждой азбуки три набора знаков (сущность `KanaSet`):

- **Базовые** — основной годзюон (46 знаков);
- **Озвончённые** — дакуон (゛) и хандакуон (゜) у серии `h`, 25 знаков;
- **Ёон** — сочетания с малыми ゃ/ゅ/ょ (включая озвончённые), 33 знака.

Для отображения и выбора каждый знак хранит позицию в таблице — строку `row` и
колонку `column`. Русская транскрипция (`ru`) выводится в справочнике рядом с ромадзи.

## Прогресс

Прогресс хранится на клиенте в `localStorage` (`entities/progress`). Каждый ответ
учитывается по знаку (попытки / верные), а по этим данным вычисляется уровень
освоения — он виден точками в таблице выбора знаков:

- серый — новый, розовый — учу, синий — практикую, зелёный — освоен.

Слой прогресса изолирован за провайдером и `useProgress`; когда появится бэкенд,
достаточно заменить `progressStorage` на сетевые вызовы, не трогая компоненты.
Сбросить весь прогресс можно кнопкой на экране настройки.
